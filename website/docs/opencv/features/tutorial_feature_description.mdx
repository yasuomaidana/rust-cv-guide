## Goal

Describe detected keypoints with 256-bit binary descriptors and match them between two views, as OpenCV's `DescriptorExtractor` and `BFMatcher(NORM_HAMMING)` do. Two crates are compared across diverse photographs: `imageproc` (FAST-9 corners + local 31×31 integral-image BRIEF) and `oximedia-cv` (`OrbExtractor` + `match_descriptors`).

## Theory

A binary descriptor turns a patch around each keypoint into 256 bits by comparing pairs of pixel intensities: bit `i` is `1` if the first sample is darker than the second. Two patches match when their bit strings are close in **Hamming distance** (number of differing bits, computed in one CPU instruction with `popcnt`).

- **Local 31×31 BRIEF (`imageproc`)** averages 5×5 sub-patches via an integral image inside a 31×31 window around each FAST-9 corner, so the descriptor reflects local texture and stays accurate even on soft or repetitive scenes.
- **Wide-radius BRIEF (`oximedia-cv`)** detects 3×3 intensity local maxima and compares point pairs up to ±256 pixels away from the keypoint without smoothing or orientation normalization. On scenes with broad smooth gradients or small cropped objects, distant pairs clamp to image borders and produce more false matches.
- **Rotation and scale**: neither crate estimates keypoint orientation or multi-scale pyramids, so matching succeeds on translated or mildly relit views (`shift = (12, 7)`) and fails when the object is rotated, scaled, or perspective-warped (`box.png` in `box_in_scene.png`).

```rust
//! OpenCV tutorial `tutorial_feature_description` in pure Rust: FAST-9 keypoints + 256-bit BRIEF descriptors.
//! Run with `cargo run -p cvg-snippets --example brief_match`.

use cvg_snippets::vis::{ConsensusResult, MatchPair, consensus_matches, match_report};
use image::GrayImage;
use imageproc::{
    binary_descriptors::{
        BinaryDescriptor,
        brief::{BriefDescriptor, TestPair, brief},
    },
    corners::corners_fast9,
    point::Point,
};

/// A deterministic set of 256 BRIEF test pairs inside the 31x31 patch (`0..31`), so results are repeatable in tests and WASM.
pub fn fixed_pairs() -> Vec<TestPair> {
    let mut state = 0x5EED_CAFE_1234_5678_u64;
    let mut next_coord = || {
        state = state
            .wrapping_mul(6_364_136_223_846_793_005)
            .wrapping_add(1_442_695_040_888_963_407);
        ((state >> 32) % 31) as u32
    };
    (0..256)
        .map(|_| TestPair {
            p0: Point::new(next_coord(), next_coord()),
            p1: Point::new(next_coord(), next_coord()),
        })
        .collect()
}

/// Extracts at most `max` FAST-9 corners (keeping 17 px clear of edges for the 31x31 BRIEF patch) and computes 256-bit BRIEF descriptors.
pub fn extract_brief(input: &GrayImage, threshold: u8, max: usize) -> Vec<BriefDescriptor> {
    let (w, h) = input.dimensions();
    if w <= 34 || h <= 34 {
        return Vec::new();
    }
    let mut corners = corners_fast9(input, threshold);
    corners.retain(|c| c.x > 16 && c.x + 16 < w && c.y > 16 && c.y + 16 < h);
    corners.sort_by(|a, b| b.score.total_cmp(&a.score));
    corners.truncate(max);
    let points: Vec<Point<u32>> = corners.iter().map(|c| Point::new(c.x, c.y)).collect();
    if points.is_empty() {
        return Vec::new();
    }
    brief(input, &points, 256, Some(&fixed_pairs()))
        .expect("keypoints stay 17 px inside borders")
        .0
}

/// Matches each descriptor in `query` to its nearest Hamming neighbour in `train` within `max_dist`.
pub fn match_two(
    query: &GrayImage,
    train: &GrayImage,
    threshold: u8,
    max: usize,
    max_dist: u32,
) -> ConsensusResult {
    let da = extract_brief(query, threshold, max);
    let db = extract_brief(train, threshold, max);
    let pairs: Vec<MatchPair> = da
        .iter()
        .filter_map(|a| {
            let (b, dist) = db
                .iter()
                .map(|b| (b, a.hamming_distance(b)))
                .min_by_key(|&(_, d)| d)?;
            (dist <= max_dist).then_some((
                (a.corner.x as f32, a.corner.y as f32),
                (b.corner.x as f32, b.corner.y as f32),
            ))
        })
        .collect();
    consensus_matches(&pairs, 2.0)
}

/// Default settings used on the guide page.
pub const THRESHOLD: u8 = 20;
pub const MAX: usize = 250;
pub const MAX_DIST: u32 = 32;

/// Evaluates translation shift recovery across four diverse photographs.
pub fn report() -> String {
    match_report(match_two, THRESHOLD, MAX, MAX_DIST)
}

pub fn main() {
    println!("{}", report());
}
```

//! OpenCV tutorial `tutorial_feature_description` with `oximedia-cv` (`OrbExtractor` + `match_descriptors`).
//! Run with `cargo run -p cvg-snippets --example oxi_orb_match`.

use cvg_snippets::vis::{ConsensusResult, MatchPair, consensus_matches, match_report};
use image::GrayImage;
use oximedia_cv::feature_extract::{OrbExtractor, match_descriptors};

/// Matches `OrbExtractor` binary descriptors between `query` and `train` within `max_dist` Hamming bits.
pub fn match_two(
    query: &GrayImage,
    train: &GrayImage,
    threshold: u8,
    max: usize,
    max_dist: u32,
) -> ConsensusResult {
    let to_unit = |img: &GrayImage| {
        img.as_raw()
            .iter()
            .map(|p| f32::from(*p) / 255.0)
            .collect::<Vec<_>>()
    };
    let extractor = OrbExtractor {
        max_features: max,
        fast_threshold: f32::from(threshold) / 255.0,
    };
    let (ka, da) = extractor.extract(
        &to_unit(query),
        query.width() as usize,
        query.height() as usize,
    );
    let (kb, db) = extractor.extract(
        &to_unit(train),
        train.width() as usize,
        train.height() as usize,
    );
    let pairs: Vec<MatchPair> = match_descriptors(&da, &db, max_dist)
        .into_iter()
        .map(|(i, j, _)| ((ka[i].x, ka[i].y), (kb[j].x, kb[j].y)))
        .collect();
    consensus_matches(&pairs, 2.0)
}

/// Default settings used on the guide page.
pub const THRESHOLD: u8 = 20;
pub const MAX: usize = 250;
pub const MAX_DIST: u32 = 24;

/// Evaluates translation shift recovery across four diverse photographs.
pub fn report() -> String {
    match_report(match_two, THRESHOLD, MAX, MAX_DIST)
}

pub fn main() {
    println!("{}", report());
}

## Explanation

1. `fixed_pairs()` generates a deterministic 256-pair sampling pattern inside a 31×31 patch so descriptor comparison is reproducible across runs and in WebAssembly.
2. `extract_brief` keeps FAST-9 corners at least 17 pixels inside the image borders (required by `imageproc::binary_descriptors::brief::brief`), keeps the `max` strongest by score, and computes 256-bit descriptors.
3. `match_two` pairs each descriptor in the first view with its closest Hamming match in the second view within `max_dist`, then uses `consensus_matches` to find the translation `(dx, dy)` most pairs agree on (green lines = consensus inliers, red = outliers).
4. Evaluating both crates across multiple scenes shows why descriptor locality and contrast-based keypoints matter: under a `(12, 7)` shift, `imageproc` FAST+BRIEF gets `213/216` inliers on `building.jpg`, `250/250` on `astronaut.png`, `227/227` on `chelsea.png`, and `246/247` on `coins.png`, and also recovers `(12, 7)` on `coffee.png`, `invoice.png`, and under a `+20` brightness shift. `oximedia-cv` recovers `(12, 7)` on the five natural unbrightened photos (`99/103` on `building`, `235/242` on `astronaut`, `89/226` on `chelsea`, `236/236` on `coins`, plus `coffee`), but loses consensus on `invoice.png` (repetitive white-background text) and under a `+20` brightness shift (because its detector ranks keypoints by raw pixel brightness, which saturates at `255`). Both crates fail to form a rigid-translation consensus on rotated/scaled `box.png` vs `box_in_scene.png` and perspective-warped `invoice.png` vs `invoice_photo.png`.
