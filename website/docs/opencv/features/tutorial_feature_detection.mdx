## Goal

Find keypoints in a photograph: places that can be found again in another picture of the same scene. Two crates do it,
`imageproc` (FAST corners) and `oximedia-cv` (an ORB-style detector that also computes binary descriptors, so keypoints can
be matched). The page shows both and runs both on the same image. The two are different detectors, not two versions of one.

## Theory

A good keypoint is distinctive and repeatable. FAST looks at 16 pixels on a circle around each pixel and calls it a corner
when a run of them is all brighter or all darker than the centre by a threshold; it is very fast and gives many corners.
ORB-style detectors add a descriptor: a short string of bits, each the result of comparing two pixels around the keypoint,
so two keypoints are the same when their bit strings are close in Hamming distance. That is what makes matching possible.

```rust
//! OpenCV tutorial `tutorial_feature_detection` in pure Rust: corner keypoints with FAST.
//! Run with `cargo run -p cvg-snippets --example fast`.

use cvg_snippets::common::gray_sample;
use image::GrayImage;
use imageproc::corners::corners_fast9;

/// The `max` strongest FAST-9 corners whose ring differs from the centre by more than `threshold` levels.
pub fn keypoints(input: &GrayImage, threshold: u8, max: usize) -> Vec<(f32, f32)> {
    let mut corners = corners_fast9(input, threshold);
    corners.sort_by(|a, b| b.score.total_cmp(&a.score));
    corners.truncate(max);
    corners.iter().map(|c| (c.x as f32, c.y as f32)).collect()
}

/// Settings the page starts with.
pub const THRESHOLD: u8 = 20;
pub const MAX: usize = 300;

/// How many corners the building photo has above the threshold, and how many the page keeps.
pub fn report() -> String {
    let photo = gray_sample("building.jpg");
    let all = keypoints(&photo, THRESHOLD, usize::MAX).len();
    let kept = keypoints(&photo, THRESHOLD, MAX).len();
    format!("corners = {all}\nkept = {kept}")
}

pub fn main() {
    println!("{}", report());
}
```

```rust
//! OpenCV tutorial `tutorial_feature_detection` and `tutorial_feature_description` with `oximedia-cv`'s ORB-style extractor:
//! keypoints, binary descriptors, and matching between two views.
//! Run with `cargo run -p cvg-snippets --example oxi_orb`.

use cvg_snippets::common::gray_sample;
use image::{GrayImage, imageops};
use oximedia_cv::feature_extract::{OrbExtractor, match_descriptors};
use std::collections::BTreeMap;

/// Grey levels as the 0 to 1 floats the extractor takes.
fn unit(image: &GrayImage) -> Vec<f32> {
    image
        .as_raw()
        .iter()
        .map(|p| f32::from(*p) / 255.0)
        .collect()
}

/// Keypoints and their binary descriptors; `threshold` is on the 0 to 255 scale.
fn extract(
    input: &GrayImage,
    threshold: u8,
    max: usize,
) -> (
    Vec<(f32, f32)>,
    Vec<oximedia_cv::feature_extract::BriefDescriptor>,
) {
    let extractor = OrbExtractor {
        max_features: max,
        fast_threshold: f32::from(threshold) / 255.0,
    };
    let (points, descriptors) = extractor.extract(
        &unit(input),
        input.width() as usize,
        input.height() as usize,
    );
    (points.iter().map(|k| (k.x, k.y)).collect(), descriptors)
}

/// The `max` strongest keypoints.
pub fn keypoints(input: &GrayImage, threshold: u8, max: usize) -> Vec<(f32, f32)> {
    extract(input, threshold, max).0
}

/// Matches the picture against a copy cropped by `(dx, dy)` and returns the shift most matches agree on, with how many do.
pub fn recovered_shift(
    input: &GrayImage,
    dx: u32,
    dy: u32,
    max: usize,
) -> Option<((i32, i32), usize)> {
    let moved =
        imageops::crop_imm(input, dx, dy, input.width() - dx, input.height() - dy).to_image();
    let (first, first_descriptors) = extract(input, THRESHOLD, max);
    let (second, second_descriptors) = extract(&moved, THRESHOLD, max);
    let mut votes: BTreeMap<(i32, i32), usize> = BTreeMap::new();
    for (i, j, _) in match_descriptors(&first_descriptors, &second_descriptors, 20) {
        let shift = (
            (first[i].0 - second[j].0).round() as i32,
            (first[i].1 - second[j].1).round() as i32,
        );
        *votes.entry(shift).or_default() += 1;
    }
    votes.into_iter().max_by_key(|(_, count)| *count)
}

/// Settings the page starts with.
pub const THRESHOLD: u8 = 20;
pub const MAX: usize = 300;

/// How many keypoints the building photo gives, and the shift recovered by matching it against a copy cropped by (12, 7).
pub fn report() -> String {
    let photo = gray_sample("building.jpg");
    let found = keypoints(&photo, THRESHOLD, MAX).len();
    let shift = recovered_shift(&photo, 12, 7, MAX);
    format!("keypoints = {found}\nshift = {shift:?}")
}

pub fn main() {
    println!("{}", report());
}
```

## Explanation

1. `corners_fast9(&image, threshold)` returns every FAST-9 corner with a score; the example keeps the `max` strongest.
2. `OrbExtractor { max_features, fast_threshold }.extract(..)` takes grey levels as floats from 0 to 1 and returns keypoints and 256-bit descriptors. Its keypoints come from a scale-space blob detector, so they are not the same places as FAST's corners.
3. `match_descriptors(&a, &b, max_distance)` pairs each descriptor of `a` with its nearest in `b` by Hamming distance. The example crops the photo by (12, 7), matches the two views, and takes the shift most matches agree on: it recovers (12, 7) from 127 matches.
4. The descriptors are not rotation invariant, so this matching works for translated views, not rotated ones.
5. The tests check what the two detectors share: after the picture is shifted, at least 95 % of the keypoints of either are found again at the shifted place.

## OpenCV to Rust

| OpenCV 5.1 | Rust |
|---|---|
| `cv::FAST(img, keypoints, threshold)` | `imageproc::corners::corners_fast9` |
| `cv::ORB::create(n)->detectAndCompute(..)` | `oximedia_cv::feature_extract::OrbExtractor::extract` |
| `cv::BFMatcher(NORM_HAMMING).match(..)` | `oximedia_cv::feature_extract::match_descriptors` |
| `cv::drawKeypoints` | `common::draw_points`, a few lines |
