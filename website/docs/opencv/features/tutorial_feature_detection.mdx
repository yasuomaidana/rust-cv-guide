## Goal

Find keypoints in a photograph: places that can be found again in another picture of the same scene. Both `imageproc`
and `oximedia-cv` detect **FAST-9** corners, and the page lets you choose the **same algorithm** on both crates and tune
their inputs either together or independently. Both keep only the strongest corner of each 3×3 neighbourhood (non-max
suppression), as OpenCV does.

## Theory

A good keypoint is distinctive and repeatable. **FAST-9** looks at 16 pixels on a circle around each pixel and calls it
a corner when 9 consecutive ring pixels are all brighter or all darker than the centre by a threshold; it is very fast and
gives many corners. **Descriptor-ready** keypoints stay far enough from the border for a 31×31 BRIEF patch, so two views can
be matched by Hamming distance (see [Feature Description](./tutorial_feature_description)). `imageproc` can also add an
orientation to each corner (`oriented_fast`).

## Code

Both crates expose the matching algorithm pair:

- **FAST-9**: `imageproc::corners::corners_fast9` (thinned by the guide's `suppress_non_max`) beside `oximedia_cv::detect::corner::FastDetector` (with non-maximum suppression).
- **Descriptor-ready**: `imageproc::corners::oriented_fast` beside the same `FastDetector` kept 17 pixels from the border, both described by the shared BRIEF.

```rust
//! OpenCV tutorial `tutorial_feature_detection` in pure Rust (`imageproc`):
//! supports both FAST-9 corners (with non-max suppression) and oriented FAST keypoints.
//! Run with `cargo run -p cvg-snippets --example fast`.

use cvg_snippets::brief::suppress_non_max;
use cvg_snippets::common::{FeatureAlgorithm, gray_sample};
use image::GrayImage;
use imageproc::corners::{corners_fast9, oriented_fast};

pub type Algorithm = FeatureAlgorithm;

/// The `max` strongest FAST-9 corners whose ring differs from the centre by more than `threshold` levels.
/// `corners_fast9` reports every pixel that passes the test, so adjacent hits are thinned to the strongest
/// of their 3x3 neighbourhood first, as OpenCV's `FastFeatureDetector` does.
pub fn keypoints(input: &GrayImage, threshold: u8, max: usize) -> Vec<(f32, f32)> {
    let all: Vec<(u32, u32, f32)> = corners_fast9(input, threshold)
        .iter()
        .map(|c| (c.x, c.y, c.score))
        .collect();
    let mut kept = suppress_non_max(&all);
    kept.sort_by(|a, b| b.2.total_cmp(&a.2));
    kept.truncate(max);
    kept.iter().map(|&(x, y, _)| (x as f32, y as f32)).collect()
}

/// ORB-style oriented FAST-9 keypoints (`edge_radius = 18`, keeping >= 17 px margin for BRIEF's 31×31 patch).
pub fn orb_keypoints(input: &GrayImage, threshold: u8, max: usize) -> Vec<(f32, f32)> {
    if input.width() <= 36 || input.height() <= 36 {
        return Vec::new();
    }
    oriented_fast(input, Some(threshold), max, 18, Some(1))
        .into_iter()
        .map(|c| (c.corner.x as f32, c.corner.y as f32))
        .collect()
}

/// Dispatches either FAST-9 or ORB-style keypoint detection with the shared `(threshold, max)` controls.
pub fn detect(input: &GrayImage, algo: Algorithm, threshold: u8, max: usize) -> Vec<(f32, f32)> {
    algo.run(input, threshold, max, keypoints, orb_keypoints)
}

/// Settings the page starts with.
pub const THRESHOLD: u8 = 20;
pub const MAX: usize = 300;

/// Counts FAST-9 corners (after non-max suppression) and ORB-style keypoints on the building photo.
pub fn report() -> String {
    let photo = gray_sample("building.jpg");
    let all = keypoints(&photo, THRESHOLD, usize::MAX).len();
    let kept = keypoints(&photo, THRESHOLD, MAX).len();
    let orb_kept = orb_keypoints(&photo, THRESHOLD, MAX).len();
    format!("corners = {all}\nkept = {kept}\norb_kept = {orb_kept}")
}

pub fn main() {
    println!("{}", report());
}
```

```rust
//! OpenCV tutorial `tutorial_feature_detection` with `oximedia-cv`: FAST-9 corners from
//! `oximedia_cv::detect::corner::FastDetector`, with non-max suppression. Describing and matching the
//! keypoints is the `tutorial_feature_description` example.
//! Run with `cargo run -p cvg-snippets --example oxi_orb`.

use cvg_snippets::brief;
use cvg_snippets::common::{FeatureAlgorithm, gray_sample};
use cvg_snippets::oxi_features::corners;
use image::GrayImage;

pub type Algorithm = FeatureAlgorithm;

/// Corners that `oximedia-cv` finds, as the `(x, y)` pixel positions the pages draw.
fn positions(input: &GrayImage, threshold: u8, max: usize, margin: u32) -> Vec<(f32, f32)> {
    corners(input, threshold, max, margin)
        .into_iter()
        .map(|(x, y)| (x as f32, y as f32))
        .collect()
}

/// The `max` strongest FAST-9 corners after non-max suppression.
pub fn fast_keypoints(input: &GrayImage, threshold: u8, max: usize) -> Vec<(f32, f32)> {
    positions(input, threshold, max, 0)
}

/// The same corners, kept clear of the border so a 31x31 descriptor patch fits. `oximedia-cv` has no
/// orientation step, so these are the positions the oriented-FAST option of `imageproc` is compared at.
pub fn keypoints(input: &GrayImage, threshold: u8, max: usize) -> Vec<(f32, f32)> {
    positions(input, threshold, max, brief::MARGIN)
}

/// Dispatches either border-free FAST-9 or descriptor-ready keypoint detection with the shared `(threshold, max)` controls.
pub fn detect(input: &GrayImage, algo: Algorithm, threshold: u8, max: usize) -> Vec<(f32, f32)> {
    algo.run(input, threshold, max, fast_keypoints, keypoints)
}

/// Settings the page starts with.
pub const THRESHOLD: u8 = 20;
pub const MAX: usize = 300;

/// Reports FAST-9 counts on the building photo.
pub fn report() -> String {
    let photo = gray_sample("building.jpg");
    let [all, kept] = [usize::MAX, MAX].map(|cap| fast_keypoints(&photo, THRESHOLD, cap).len());
    let described = keypoints(&photo, THRESHOLD, MAX).len();
    format!("corners = {all}\nkept = {kept}\ndescribed = {described}")
}

pub fn main() {
    println!("{}", report());
}
```

## Explanation

1. Selecting **FAST-9** runs `corners_fast9` (`imageproc`) beside `FastDetector::new().with_threshold(..).with_nms(true)` (`oximedia-cv`), keeping the `max` strongest corners.
2. Selecting **Descriptor-ready** runs `oriented_fast` (`imageproc`, FAST-9 with intensity-centroid orientation) beside `FastDetector` kept clear of the border (`oximedia-cv` has no orientation step, so only the positions are comparable). `oximedia_cv::feature_extract::OrbExtractor` is not used: despite its name it runs a scale-space (SIFT) detector, so its keypoints cannot be compared with FAST.
3. Describing these keypoints with a 256-bit BRIEF and matching them between two views is the [Feature Description](./tutorial_feature_description) tutorial, which runs the same pipeline on both crates.
4. Use the **Sync parameters** checkbox in the live demo below to compare both crates on identical inputs, or uncheck it to pick a different algorithm, threshold, or keypoint cap per crate.

## OpenCV to Rust

| OpenCV 5.1 | Rust |
|---|---|
| `cv::FAST(img, keypoints, threshold, true)` | `imageproc::corners::corners_fast9` + non-max suppression, or `oximedia_cv::detect::corner::FastDetector` |
| `cv::ORB::create(n)->detect(..)` | `imageproc::corners::oriented_fast` |
| `cv::BFMatcher(NORM_HAMMING).match(..)` | `imageproc::binary_descriptors::match_binary_descriptors` or `oximedia_cv::feature_extract::match_descriptors` |
| `cv::drawKeypoints` | `common::draw_points`, a few lines |

## Performance comparison

| Operation | Input | OpenCV | Pure Rust | oximedia / oxipix | oxi / Rust |
|---|---|---|---|---|---|
| FAST-9 corners (t=30, 3x3 non-max suppression, uncapped) | 868x600 grey | 0.579 ms | 3.210 ms | 6.966 ms | 2.17x |
| Oriented keypoints (t=30, max=250) | 868x600 grey | 6.599 ms | 2.312 ms | 6.967 ms | 3.01x |

:::warning Performance difference

- **FAST-9 corners (t=30, 3x3 non-max suppression, uncapped):** oximedia-cv's FastDetector misses corners whose 9-pixel arc wraps around the ring (1424 corners against 2091 in OpenCV and 2204 in imageproc), so its time is for less work. Known difference, see PERF_QUEUE.md.
- **Oriented keypoints (t=30, max=250):** oximedia-cv's FastDetector (about 7 ms) is about 3x slower than imageproc's oriented FAST (about 2 ms) on the same 868x600 photo. Tracked in the perf queue under feature_detection_fast and feature_description.

:::
