## Goal

Shrink and grow the bright regions of a binary image with erosion and dilation, the two basic morphological operations
behind `cv::erode` and `cv::dilate`. Both `imageproc` and `oximedia-cv` implement them, so the page compares both side by side.

## Theory

Both slide a small shape, the structuring element, over the image. **Erosion** keeps a pixel only if the whole element fits
inside the bright region around it, so bright regions shrink and thin bridges disappear. **Dilation** switches a pixel on if
the element touches any bright pixel, so regions grow and small holes fill. They are duals: dilating the bright regions is
eroding the dark ones.

```rust
//! OpenCV tutorial `tutorial_erosion_dilatation` in pure Rust.
//! Run with `cargo run -p cvg-snippets --example erosion`.

use cvg_snippets::common::{Figure, MorphOps, morph_figures, white_pixel_report};
use image::GrayImage;
use imageproc::contrast::{ThresholdType, otsu_level, threshold};
use imageproc::distance_transform::Norm;
use imageproc::morphology::{dilate, erode};

/// The coin mask: bright pixels above Otsu's level.
pub fn coin_mask(grey: &GrayImage) -> GrayImage {
    threshold(grey, otsu_level(grey), ThresholdType::Binary)
}

/// Erosion with a square window of `2 * radius + 1` pixels (`Norm::LInf`).
pub fn shrink(mask: &GrayImage, radius: u8) -> GrayImage {
    erode(mask, Norm::LInf, radius)
}

/// Dilation with a square window of `2 * radius + 1` pixels (`Norm::LInf`).
pub fn grow(mask: &GrayImage, radius: u8) -> GrayImage {
    dilate(mask, Norm::LInf, radius)
}

/// The mask, erode, and dilate functions bundled for `cvg-live`.
pub const OPS: MorphOps = (coin_mask, shrink, grow);

/// The coin mask, eroded and dilated with a 5x5 square (radius 2).
pub fn figures() -> Vec<Figure> {
    morph_figures(OPS)
}

/// How many pixels each figure has switched on: erosion shrinks the coins, dilation grows them.
pub fn report() -> String {
    white_pixel_report(figures())
}

pub fn main() {
    println!("{}", report());
}
```

```rust
//! OpenCV tutorial `tutorial_erosion_dilatation` using `oximedia-cv::image::morph` and `oxipix::otsu_threshold`.
//! Run with `cargo run -p cvg-snippets --example oxi_erosion`.

use cvg_snippets::{
    common::{Figure, MorphOps, morph_figures, white_pixel_report},
    oxi,
};
use image::{GrayImage, Luma};
use oximedia_cv::image::morph::{dilate, erode};
use oxipix::vectorize::otsu_threshold;

/// The coin mask: bright pixels above Otsu's level.
pub fn coin_mask(grey: &GrayImage) -> GrayImage {
    let level = otsu_threshold(grey.as_raw());
    GrayImage::from_fn(grey.width(), grey.height(), |x, y| {
        Luma([if grey.get_pixel(x, y).0[0] > level {
            255
        } else {
            0
        }])
    })
}

/// Erosion with a square structuring element of `2 * radius + 1` pixels.
pub fn shrink(mask: &GrayImage, radius: u8) -> GrayImage {
    oxi::morph(mask, erode, radius)
}

/// Dilation with a square structuring element of `2 * radius + 1` pixels.
pub fn grow(mask: &GrayImage, radius: u8) -> GrayImage {
    oxi::morph(mask, dilate, radius)
}

/// The mask, erode, and dilate functions bundled for `cvg-live`.
pub const OPS: MorphOps = (coin_mask, shrink, grow);

/// The coin mask, eroded and dilated with a 5x5 square (radius 2).
pub fn figures() -> Vec<Figure> {
    morph_figures(OPS)
}

/// Counts white pixels before and after erosion/dilation.
pub fn report() -> String {
    white_pixel_report(figures())
}

pub fn main() {
    println!("{}", report());
}
```

## Explanation

1. A mask is made by thresholding the coins photograph with Otsu's level (`imageproc::contrast::otsu_level` or `oxipix::vectorize::otsu_threshold`), so coins are white (255) on black.
2. `Norm::LInf` with `k = 2` (`imageproc`) and `StructuringElement::rectangle(5, 5)` (`oximedia-cv`) both represent a 5×5 square window (`getStructuringElement(MORPH_RECT, Size(5, 5))`).
3. `erode` and `dilate` return new images and leave the mask untouched; tests verify exact equality between `imageproc` and `oximedia-cv`.
4. `report` counts white pixels, which shows the effect as a number.

## OpenCV to Rust

| OpenCV 5.1 | Rust |
|---|---|
| `cv::getStructuringElement(MORPH_RECT, Size(5, 5))` | `Norm::LInf` with `k = 2` (`imageproc`), or `oximedia_cv::image::StructuringElement::rectangle(5, 5)` |
| `cv::erode(src, dst, element)` | `imageproc::morphology::erode` or `oximedia_cv::image::morph::erode` |
| `cv::dilate(src, dst, element)` | `imageproc::morphology::dilate` or `oximedia_cv::image::morph::dilate` |

## Performance comparison

| Operation | Input | OpenCV | Pure Rust | oximedia / oxipix | oxi / Rust |
|---|---|---|---|---|---|
| Erode (5x5 square, r=2) | 384x303 grey | 0.010 ms | 0.275 ms | 3.293 ms | 11.97x |

:::warning Performance difference

- **Erode (5x5 square, r=2):** oximedia-cv erode is 11.4x slower than imageproc (335x slower than OpenCV) because StructuringElement::iter_active recomputes (i % w, i / w) offsets and checks bounds per tap with no separable rectangular fast path (cool-japan/oximedia#30).

:::
