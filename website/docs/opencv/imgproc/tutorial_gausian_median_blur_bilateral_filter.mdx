## Goal

Smooth a photograph four ways, as the OpenCV tutorial does with `blur`, `GaussianBlur`, `medianBlur` and `bilateralFilter`, and see how each
treats noise and edges. Two crates do the job, `imageproc` and `oximedia-cv`, so the page shows both and runs both on the same image.

## Theory

Smoothing replaces each pixel with a combination of its neighbours, which suppresses noise at the price of blurring detail.

- **Box** (normalised) filter: the plain average of a window. Fast, but it smears edges evenly.
- **Gaussian** filter: a weighted average whose weights fall off as a bell curve with spread `σ`, so close neighbours count more.
- **Median** filter: the middle value of the window. It is not a weighted sum, so it removes isolated outliers (salt-and-pepper noise) without averaging them in.
- **Bilateral** filter: a Gaussian whose weights also fall off with the *difference in level*, so it blurs flat areas and leaves edges alone.

## Code

`imageproc::filter` has the Gaussian, the median and the bilateral filter for any pixel type. `oximedia-cv` has all four (`BoxBlur`, `GaussianBlur`, `MedianFilter`, `BilateralFilter`) but only for grey bytes, so the example filters each colour plane on its own; the two crates are tested to agree within about one grey level. There is no ready-made colour box filter
(`filter::box_filter` takes grey images only), but a box is a separable kernel of equal weights, so
`separable_filter_equal` does it.

```rust
//! OpenCV tutorial `tutorial_gausian_median_blur_bilateral_filter` in pure Rust.
//! Run with `cargo run -p cvg-snippets --example smoothing`.

use cvg_snippets::common::{Figure, Smoothers, describe, smoothing_figures};
use image::RgbImage;
use imageproc::filter::{
    bilateral::{GaussianEuclideanColorDistance, bilateral_filter},
    gaussian_blur_f32, median_filter, separable_filter_equal,
};

/// Normalised box filter (`cv::blur`) over a square window of `2 * radius + 1` pixels.
pub fn box_blur(input: &RgbImage, radius: u32) -> RgbImage {
    let taps = (2 * radius + 1) as usize;
    separable_filter_equal(input, &vec![1.0 / taps as f32; taps])
}

/// Gaussian filter (`cv::GaussianBlur`) with spread `sigma`.
pub fn gaussian(input: &RgbImage, sigma: f32) -> RgbImage {
    gaussian_blur_f32(input, sigma)
}

/// Median filter (`cv::medianBlur`) over a square window of `2 * radius + 1` pixels.
pub fn median(input: &RgbImage, radius: u32) -> RgbImage {
    median_filter(input, radius, radius)
}

/// Edge-preserving smoothing (`cv::bilateralFilter`); `sigma_color` says how different two levels may be and still mix.
pub fn bilateral(input: &RgbImage, radius: u32, sigma_color: f32) -> RgbImage {
    let color = GaussianEuclideanColorDistance::new(sigma_color);
    bilateral_filter(input, radius.min(255) as u8, radius as f32, color)
}

/// The photo and four 5x5 smoothings of it.
pub fn figures() -> Vec<Figure> {
    smoothing_figures(&Smoothers {
        box_blur,
        gaussian,
        median,
        bilateral,
    })
}

/// Describes one pixel of each figure.
pub fn report() -> String {
    describe(&figures(), 225, 150)
}

pub fn main() {
    println!("{}", report());
}
```

```rust
//! OpenCV tutorial `tutorial_gausian_median_blur_bilateral_filter` with `oximedia-cv` instead of `imageproc`.
//! Run with `cargo run -p cvg-snippets --example oxi_smoothing`.

use cvg_snippets::{
    common::{Figure, Smoothers, describe, smoothing_figures},
    oxi,
};
use image::RgbImage;
use oximedia_cv::image::{BilateralFilter, BoxBlur, GaussianBlur, MedianFilter};

/// Window size of `2 * radius + 1`, the width oximedia filters take.
fn window(radius: u32) -> usize {
    (2 * radius + 1) as usize
}

/// Normalised box filter (`cv::blur`); oximedia filters are grey, so each colour plane is filtered on its own.
pub fn box_blur(input: &RgbImage, radius: u32) -> RgbImage {
    oxi::per_channel(input, |plane| {
        oxi::filter(plane, &BoxBlur::new(window(radius)))
    })
}

/// Gaussian filter (`cv::GaussianBlur`) with spread `sigma` over a window that covers three sigmas each way.
pub fn gaussian(input: &RgbImage, sigma: f32) -> RgbImage {
    let radius = (3.0 * sigma).ceil() as u32;
    let blur = GaussianBlur::new(sigma.into(), window(radius));
    oxi::per_channel(input, |plane| oxi::filter(plane, &blur))
}

/// Median filter (`cv::medianBlur`) over a window of `2 * radius + 1` pixels.
pub fn median(input: &RgbImage, radius: u32) -> RgbImage {
    oxi::per_channel(input, |plane| {
        oxi::filter(plane, &MedianFilter::new(window(radius)))
    })
}

/// Edge-preserving smoothing (`cv::bilateralFilter`); `sigma_color` says how different two levels may be and still mix.
pub fn bilateral(input: &RgbImage, radius: u32, sigma_color: f32) -> RgbImage {
    let filter = BilateralFilter::new(radius.into(), sigma_color.into(), window(radius));
    oxi::per_channel(input, |plane| oxi::filter(plane, &filter))
}

/// The photo and four 5x5 smoothings of it.
pub fn figures() -> Vec<Figure> {
    smoothing_figures(&Smoothers {
        box_blur,
        gaussian,
        median,
        bilateral,
    })
}

/// Describes one pixel of each figure.
pub fn report() -> String {
    describe(&figures(), 225, 150)
}

pub fn main() {
    println!("{}", report());
}
```

## Explanation

1. `sample("chelsea.png")` loads a CC0 photograph (see the attribution file in `snippets/assets/`).
2. `separable_filter_equal(&input, &[0.2; 5])` runs a five-tap average along rows then columns, which equals a normalised 5×5 box (`cv::blur(src, dst, Size(5, 5))`).
3. `gaussian_blur_f32(&input, 1.1)` uses `σ = 1.1`, what OpenCV derives for a 5-pixel kernel when `sigma` is 0.
4. `median_filter(&input, 2, 2)` takes the median over a window of radius 2, that is 5×5. Rust APIs take a radius where OpenCV takes a kernel size.
5. `bilateral_filter(&input, 2, 2.0, GaussianEuclideanColorDistance::new(30.0))` mixes only pixels within a colour distance of about 30.

## OpenCV to Rust

| OpenCV 5.1 | Rust |
|---|---|
| `cv::blur(src, dst, Size(5, 5))` | `separable_filter_equal(&img, &[0.2_f32; 5])` |
| `cv::GaussianBlur(src, dst, Size(5, 5), σ)` | `imageproc::filter::gaussian_blur_f32(&img, σ)` |
| `cv::medianBlur(src, dst, 5)` | `imageproc::filter::median_filter(&img, 2, 2)` (radius, not size), or `oximedia_cv::image::MedianFilter::new(5)` |
| `cv::bilateralFilter(src, dst, 5, 30, 2)` | `bilateral_filter(&img, 2, 2.0, GaussianEuclideanColorDistance::new(30.0))`, or `oximedia_cv::image::BilateralFilter::new(2.0, 30.0, 5)` per colour plane |

## Performance comparison

| Operation | Input | OpenCV | Pure Rust | oximedia / oxipix | oxi / Rust |
|---|---|---|---|---|---|
| Box blur (5x5, r=2) | 451x300 RGB | 0.239 ms | 1.344 ms | 2.044 ms | 1.52x |
| Gaussian blur (sigma=1.1) | 451x300 RGB | 0.198 ms | 1.728 ms | 4.695 ms | 2.72x |
| Median filter (5x5, r=2) | 451x300 RGB | 0.435 ms | 17.613 ms | 38.584 ms | 2.19x |
| Bilateral filter (d=5, r=2, sc=30) | 451x300 RGB | 0.808 ms | 9.154 ms | 32.873 ms | 3.59x |

:::warning Performance difference

- **Gaussian blur (sigma=1.1):** oximedia-cv GaussianBlur is 2.7x slower than image::imageops::blur (23.9x slower than OpenCV) due to per-channel plane splitting and generic 2D/separable float passes without integer SIMD vectorisation (cool-japan/oximedia#29).
- **Median filter (5x5, r=2):** Median 5x5 is 41.0x (imageproc) to 90.0x (oximedia-cv) slower than OpenCV: oximedia-cv heap-allocates a Vec and calls sort_unstable() at every pixel instead of using a 256-bin sliding histogram (cool-japan/oximedia#29, OXI-93).
- **Bilateral filter (d=5, r=2, sc=30):** oximedia-cv bilateral filter is 3.6x slower than imageproc (41.5x slower than OpenCV): it runs 3 grayscale passes in f64 calling f64::exp() inside the 4-deep loop without a 256-entry range LUT (cool-japan/oximedia#29, OXI-93).

:::
