## Goal

Build an image pyramid: shrink a picture by half again and again with `pyrDown`, and enlarge it with `pyrUp`, as in the OpenCV
tutorial. Both `image` + `imageproc` and `oximedia-cv` are shown side by side.

## Theory

A pyramid keeps several resolutions of one picture. Going down, each level is the previous one blurred/averaged and thinned to
half the resolution (`div_ceil(2)`). Going up doubles each side by bilinear interpolation, so down then up gives a smooth
approximation of the original rather than recovering lost high-frequency detail.

```rust
//! OpenCV tutorial `tutorial_pyramids` in pure Rust: `pyrDown` and `pyrUp`.
//! Run with `cargo run -p cvg-snippets --example pyramids`.

use cvg_snippets::common::{Figure, pyramid_report, rgb_figures, sample};
use image::{RgbImage, imageops};
use imageproc::filter::separable_filter_equal;

/// The 5-tap binomial kernel OpenCV's `pyrDown` blurs with.
const BINOMIAL: [f32; 5] = [1.0 / 16.0, 4.0 / 16.0, 6.0 / 16.0, 4.0 / 16.0, 1.0 / 16.0];

/// `cv::pyrDown`: blur, then keep every second row and column, so each side halves (rounded up).
pub fn pyr_down(input: &RgbImage) -> RgbImage {
    let blurred = separable_filter_equal(input, &BINOMIAL);
    RgbImage::from_fn(
        input.width().div_ceil(2),
        input.height().div_ceil(2),
        |x, y| *blurred.get_pixel(2 * x, 2 * y),
    )
}

/// `cv::pyrUp`: double each side with bilinear interpolation (OpenCV inserts zeros and blurs; the result is the same kind of smooth).
pub fn pyr_up(input: &RgbImage) -> RgbImage {
    imageops::resize(
        input,
        input.width() * 2,
        input.height() * 2,
        imageops::FilterType::Triangle,
    )
}

/// Goes down `levels` times, then, if `back` is set, up the same number of times: a blurred copy of the original size.
pub fn pyramid(input: &RgbImage, levels: u32, back: bool) -> RgbImage {
    let down = (0..levels).fold(input.clone(), |picture, _| pyr_down(&picture));
    if back {
        (0..levels).fold(down, |picture, _| pyr_up(&picture))
    } else {
        down
    }
}

/// The photo and three levels down, and the third level brought back up.
pub fn figures() -> Vec<Figure> {
    let input = sample("chelsea.png");
    let results = [
        ("down1", pyramid(&input, 1, false)),
        ("down2", pyramid(&input, 2, false)),
        ("down3", pyramid(&input, 3, false)),
        ("up3", pyramid(&input, 3, true)),
    ];
    rgb_figures(input.clone(), results)
}

/// Describes one pixel of each figure, then lists their sizes.
pub fn report() -> String {
    pyramid_report(&figures())
}

pub fn main() {
    println!("{}", report());
}
```

```rust
//! OpenCV tutorial `tutorial_pyramids` using `oximedia-cv::image::resize::{ImagePyramid, resize_image}`.
//! Run with `cargo run -p cvg-snippets --example oxi_pyramids`.

use cvg_snippets::common::{Figure, chelsea_variants, pyramid_report};
use image::RgbImage;
use oximedia_cv::image::resize::{ImagePyramid, ResizeConfig, ResizeMethod, resize_image};

/// Downsamples once with `ImagePyramid::gaussian` (Area resampling, `div_ceil(2)` dimensions).
pub fn pyr_down(input: &RgbImage) -> RgbImage {
    let (w, h) = input.dimensions();
    let pyramid = ImagePyramid::gaussian(input.as_raw(), w, h, 3, 2).expect("non-empty image");
    let level = pyramid.level(1).expect("level 1");
    RgbImage::from_raw(level.width, level.height, level.data.clone()).expect("rgb buffer")
}

/// Doubles each side with bilinear interpolation via `resize_image`.
pub fn pyr_up(input: &RgbImage) -> RgbImage {
    let (w, h) = input.dimensions();
    let config = ResizeConfig::new(w * 2, h * 2, ResizeMethod::Bilinear, 3);
    let data = resize_image(input.as_raw(), w, h, &config).expect("valid resize");
    RgbImage::from_raw(w * 2, h * 2, data).expect("rgb buffer")
}

/// Goes down `levels` steps using `ImagePyramid::gaussian`, then back up if `back` is true.
pub fn pyramid(input: &RgbImage, levels: u32, back: bool) -> RgbImage {
    let (w, h) = input.dimensions();
    let built = ImagePyramid::gaussian(input.as_raw(), w, h, 3, levels as usize + 1)
        .expect("non-empty image");
    let top = built.levels.last().expect("at least level 0");
    let mut current =
        RgbImage::from_raw(top.width, top.height, top.data.clone()).expect("rgb buffer");
    if back {
        for _ in 0..levels {
            current = pyr_up(&current);
        }
    }
    current
}

/// The photo and three pyramid levels down, plus level 3 brought back up.
pub fn figures() -> Vec<Figure> {
    chelsea_variants(
        [("down1", 1), ("down2", 2), ("down3", 3), ("up3", -3)],
        |img, step: i32| pyramid(img, step.unsigned_abs(), step < 0),
    )
}

/// Describes one pixel of each figure and lists their sizes.
pub fn report() -> String {
    pyramid_report(&figures())
}

pub fn main() {
    println!("{}", report());
}
```

## Explanation

1. In `imageproc`, `separable_filter_equal(input, &BINOMIAL)` blurs with `[1, 4, 6, 4, 1] / 16` before subsampling every second pixel, and `imageops::resize(..., FilterType::Triangle)` doubles each side.
2. In `oximedia-cv`, `ImagePyramid::gaussian` builds multi-scale levels using `ResizeMethod::Area` (`div_ceil(2)`), and `resize_image(..., ResizeMethod::Bilinear)` enlarges each level back up.
3. Because each side is rounded up on the way down, down three times and up three times gives 456 × 304 for a 451 × 300 photo. The live example crops the result to the input's size.

## OpenCV to Rust

| OpenCV 5.1 | Rust |
|---|---|
| `cv::pyrDown(src, dst)` | `separable_filter_equal` + subsample (`imageproc`), or `oximedia_cv::image::resize::ImagePyramid::gaussian` |
| `cv::pyrUp(src, dst)` | `imageops::resize(.., FilterType::Triangle)` or `oximedia_cv::image::resize::resize_image(.., ResizeMethod::Bilinear)` |

## Performance comparison

| Operation | Input | OpenCV | Pure Rust | oximedia / oxipix | oxi / Rust |
|---|---|---|---|---|---|
| 3-level pyrDown | 451x300 RGB | 0.045 ms | 1.822 ms | 0.878 ms | 0.48x |

:::warning Performance difference

- **3-level pyrDown:** Pure Rust imageops::resize(Gaussian) is 40.5x slower than OpenCV pyrDown (and 2.1x slower than oximedia-cv pyr_down) because it runs a full variable-radius Gaussian resampler rather than a fixed 5-tap separable pyramid downsample.

:::
