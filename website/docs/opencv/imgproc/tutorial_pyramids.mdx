## Rust crates

- [image](https://crates.io/crates/image)
- [imageproc](https://crates.io/crates/imageproc)

## Goal

Build an image pyramid: shrink a picture by half again and again with `pyrDown`, and enlarge it with `pyrUp`, as in the OpenCV
tutorial.

## Theory

A pyramid keeps several resolutions of one picture. Going down, each level is the previous one blurred and then thinned to
every second row and column; the blur is what stops the thinning from creating aliasing. Going up doubles each side, which can
only invent detail by interpolation, so down then up gives a blurred copy of the original, not the original.

## Code

```rust
//! OpenCV tutorial `tutorial_pyramids` in pure Rust: `pyrDown` and `pyrUp`.
//! Run with `cargo run -p cvg-snippets --example pyramids`.

use cvg_snippets::common::{Figure, describe, rgb_figures, sample};
use image::{RgbImage, imageops};
use imageproc::filter::separable_filter_equal;

/// The 5-tap binomial kernel OpenCV's `pyrDown` blurs with.
const BINOMIAL: [f32; 5] = [1.0 / 16.0, 4.0 / 16.0, 6.0 / 16.0, 4.0 / 16.0, 1.0 / 16.0];

/// `cv::pyrDown`: blur, then keep every second row and column, so each side halves (rounded up).
pub fn pyr_down(input: &RgbImage) -> RgbImage {
    let blurred = separable_filter_equal(input, &BINOMIAL);
    RgbImage::from_fn(
        input.width().div_ceil(2),
        input.height().div_ceil(2),
        |x, y| *blurred.get_pixel(2 * x, 2 * y),
    )
}

/// `cv::pyrUp`: double each side with bilinear interpolation (OpenCV inserts zeros and blurs; the result is the same kind of smooth).
pub fn pyr_up(input: &RgbImage) -> RgbImage {
    imageops::resize(
        input,
        input.width() * 2,
        input.height() * 2,
        imageops::FilterType::Triangle,
    )
}

/// Goes down `levels` times, then, if `back` is set, up the same number of times: a blurred copy of the original size.
pub fn pyramid(input: &RgbImage, levels: u32, back: bool) -> RgbImage {
    let down = (0..levels).fold(input.clone(), |picture, _| pyr_down(&picture));
    if back {
        (0..levels).fold(down, |picture, _| pyr_up(&picture))
    } else {
        down
    }
}

/// The photo and three levels down, and the third level brought back up.
pub fn figures() -> Vec<Figure> {
    let input = sample("chelsea.png");
    let results = [
        ("down1", pyramid(&input, 1, false)),
        ("down2", pyramid(&input, 2, false)),
        ("down3", pyramid(&input, 3, false)),
        ("up3", pyramid(&input, 3, true)),
    ];
    rgb_figures(input.clone(), results)
}

/// Describes one pixel of each figure, then lists their sizes.
pub fn report() -> String {
    let figures = figures();
    let sizes: Vec<String> = figures
        .iter()
        .map(|(_, picture)| format!("{}x{}", picture.width(), picture.height()))
        .collect();
    format!(
        "{}\nsizes = {}",
        describe(&figures, 50, 30),
        sizes.join(", ")
    )
}

pub fn main() {
    println!("{}", report());
}
```

## Explanation

1. `separable_filter_equal(input, &BINOMIAL)` blurs rows and columns with the 5-tap kernel `[1, 4, 6, 4, 1] / 16`, the Gaussian approximation `pyrDown` uses.
2. `RgbImage::from_fn(w.div_ceil(2), h.div_ceil(2), ..)` keeps every second pixel, so a side of 451 becomes 226 (OpenCV's `(w + 1) / 2`).
3. `pyr_up` doubles each side with bilinear interpolation (`FilterType::Triangle`). OpenCV inserts zero rows and columns and blurs; both produce a smooth enlargement, but the pixel values differ slightly.
4. Because each side is rounded up on the way down, down three times and up three times gives 456 × 304 for a 451 × 300 photo, not the original size. The live example crops the result to the input's size.
5. Tests check the sizes (rounding up, doubling) and that a flat picture survives down and up unchanged.

## OpenCV to Rust

| OpenCV 5.1 | Rust |
|---|---|
| `cv::pyrDown(src, dst)` | `pyr_down`: `separable_filter_equal` with `[1, 4, 6, 4, 1] / 16`, then every second pixel |
| `cv::pyrUp(src, dst)` | `pyr_up`: `imageops::resize(.., FilterType::Triangle)` to twice the size |
