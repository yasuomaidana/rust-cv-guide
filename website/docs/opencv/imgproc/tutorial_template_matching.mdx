## Rust crates

- [image](https://crates.io/crates/image)
- [imageproc](https://crates.io/crates/imageproc)

## Goal

Find where a small patch occurs in a bigger picture, as OpenCV's `matchTemplate` does. The page cuts a patch out of a photograph,
shows both the patch and the full score map, and looks for it in a relit copy with either the full rectangle or a circular mask.

## Theory

Template matching slides the template over every position of the picture and scores how well they agree there. The score
decides which position is best:

- **Sum of squared errors** (SSE) adds up the squared differences; small is good. A large brightness offset adds a constant error at every pixel, pushing the minimum elsewhere.
- **Normalised** versions divide by the energy of the two patches. `imageproc`'s normalised SSE does not subtract the patch mean (unlike OpenCV's `CCOEFF_NORMED`), so a large additive brightness shift still hurts it, whereas **normalised cross-correlation** measures cosine similarity and tolerates strong lighting changes.
- **Cross-correlation** multiplies the template with the picture; large is good. Raw, it grows wherever the picture is bright, so it prefers bright places over similar ones. Normalised, it peaks sharply on the matching shape.
- **Masks** weight which pixels inside the template count (`match_template_with_mask`), useful when matching round or irregular objects without background corners.

## Code

Neither `oximedia-cv` 0.2.1 nor `oxipix` 0.1.0 currently implements template matching. An **oxipix** feature ticket (`OXI-92`) has been opened to expose `match_template` covering `SqDiff`, `CCorr`, and `CCoeff` (including normalised variants).

```rust
//! OpenCV tutorial `tutorial_template_matching` in pure Rust: find a small patch inside a picture.
//! Run with `cargo run -p cvg-snippets --example template_matching`.

use cvg_snippets::common::gray_sample;
use image::{GrayImage, Luma, imageops};
use imageproc::{
    definitions::Image,
    template_matching::{
        MatchTemplateMethod, find_extremes, match_template, match_template_with_mask,
    },
};

/// The methods of the page, in the order its menu lists them.
pub const METHODS: [MatchTemplateMethod; 4] = [
    MatchTemplateMethod::SumOfSquaredErrors,
    MatchTemplateMethod::SumOfSquaredErrorsNormalized,
    MatchTemplateMethod::CrossCorrelation,
    MatchTemplateMethod::CrossCorrelationNormalized,
];

/// Crops a rectangular `(w x h)` patch at `(x, y)`, clamped cleanly inside `grey`.
pub fn crop_template(grey: &GrayImage, x: u32, y: u32, w: u32, h: u32) -> (GrayImage, (u32, u32)) {
    let tw = w.clamp(4, grey.width().max(4)).min(grey.width());
    let th = h.clamp(4, grey.height().max(4)).min(grey.height());
    let tx = x.min(grey.width().saturating_sub(tw));
    let ty = y.min(grey.height().saturating_sub(th));
    (
        imageops::crop_imm(grey, tx, ty, tw, th).to_image(),
        (tx, ty),
    )
}

/// A `size` x `size` patch cut from the middle of the picture, a little above the centre, and where its top left corner is.
pub fn cut_template(grey: &GrayImage, size: u32) -> (GrayImage, (u32, u32)) {
    let x = grey.width().saturating_sub(size) / 2;
    let y = (grey.height() * 2 / 5).saturating_sub(size / 2);
    crop_template(grey, x, y, size, size)
}

/// The same scene seen under a different light: slightly blurred and brightened by `brighten` levels.
pub fn relit(grey: &GrayImage, brighten: i32) -> GrayImage {
    imageops::brighten(&imageops::blur(grey, 1.5), brighten)
}

/// Elliptical mask of `width` x `height`: 255 inside the inscribed ellipse and 0 in the corners.
pub fn elliptical_mask(width: u32, height: u32) -> GrayImage {
    let cx = (width as f32 - 1.0) / 2.0;
    let cy = (height as f32 - 1.0) / 2.0;
    let rx_sq = (width as f32 / 2.0).powi(2).max(1.0);
    let ry_sq = (height as f32 / 2.0).powi(2).max(1.0);
    GrayImage::from_fn(width, height, |x, y| {
        let dx = (x as f32 - cx).powi(2) * ry_sq;
        let dy = (y as f32 - cy).powi(2) * rx_sq;
        Luma([if dx + dy <= rx_sq * ry_sq { 255 } else { 0 }])
    })
}

/// Circular mask of `size` x `size`: 255 inside the inscribed circle and 0 in the corners.
pub fn circular_mask(size: u32) -> GrayImage {
    elliptical_mask(size, size)
}

/// `cv::matchTemplate`: slides `template` over `search` (with an optional inscribed elliptical mask) and returns the score grid.
pub fn match_scores(
    search: &GrayImage,
    template: &GrayImage,
    method: MatchTemplateMethod,
    masked: bool,
) -> Image<Luma<f32>> {
    if masked {
        let mask = elliptical_mask(template.width(), template.height());
        match_template_with_mask(search, template, method, &mask)
    } else {
        match_template(search, template, method)
    }
}

/// Error measures are best at their minimum; correlations are best at their maximum.
pub fn is_error_method(method: MatchTemplateMethod) -> bool {
    matches!(
        method,
        MatchTemplateMethod::SumOfSquaredErrors | MatchTemplateMethod::SumOfSquaredErrorsNormalized
    )
}

/// `cv::minMaxLoc`: returns the top-left corner and score of the best match in `scores`.
pub fn best_match_in(scores: &Image<Luma<f32>>, method: MatchTemplateMethod) -> ((u32, u32), f32) {
    let extremes = find_extremes(scores);
    if is_error_method(method) {
        (extremes.min_value_location, extremes.min_value)
    } else {
        (extremes.max_value_location, extremes.max_value)
    }
}

/// Convenience wrapper for matching without a mask.
pub fn best_match(
    search: &GrayImage,
    template: &GrayImage,
    method: MatchTemplateMethod,
) -> (u32, u32) {
    best_match_in(&match_scores(search, template, method, false), method).0
}

/// Size and brightness shift the page starts with.
pub const SIZE: u32 = 40;
pub const BRIGHTEN: i32 = 50;

/// Where the patch was cut, and where each method (plus masked normalised correlation) finds it in the relit picture.
pub fn report() -> String {
    let photo = gray_sample("chelsea.png");
    let (template, corner) = cut_template(&photo, SIZE);
    let search = relit(&photo, BRIGHTEN);
    let names = ["sse", "sse_normed", "ccorr", "ccorr_normed"];
    let mut lines: Vec<String> = METHODS
        .iter()
        .zip(names)
        .map(|(method, name)| format!("{name} = {:?}", best_match(&search, &template, *method)))
        .collect();
    let masked = best_match_in(
        &match_scores(
            &search,
            &template,
            MatchTemplateMethod::CrossCorrelationNormalized,
            true,
        ),
        MatchTemplateMethod::CrossCorrelationNormalized,
    );
    lines.push(format!("ccorr_normed_masked = {:?}", masked.0));
    format!("template = {corner:?}\n{}", lines.join("\n"))
}

pub fn main() {
    println!("{}", report());
}
```

## Explanation

1. `crop_template` (and `cut_template` for the default 40×40 patch) crops a patch from the photo and remembers its top-left corner (drawn in green in the live view).
2. `relit` blurs the photo slightly and adds `brighten` levels, so the match is not a trivial copy.
3. `elliptical_mask` (and `circular_mask` for square patches) keeps pixels inside the inscribed ellipse (`255`) and zeros out the corners (`0`), letting `match_template_with_mask` ignore background corners even on non-square mouse selections.
4. `match_scores` runs either `match_template` or `match_template_with_mask`, and `best_match_in` (`minMaxLoc`) picks the minimum for error measures or the maximum for correlations.
5. For the page's default settings (`size = 40`, `brighten = 50`), the patch is cut at `(205, 100)`. Raw `SSE` drifts to `(308, 109)`, raw `CCORR` jumps to the bright corner `(411, 235)`, and `CCORR_NORMED` (both full and circularly masked) finds `(204, 100)`, within one pixel of the cut.
6. Tests check that every method except raw correlation finds the exact corner in an untouched copy, that raw SSE breaks between `+25` and `+50` brightness shift while `CCORR_NORMED` stays within 2 pixels (with and without a mask), and that `report()` matches the numbers below. `imageproc` has four of OpenCV's six methods (no zero-mean `CCOEFF`) and uses a sliding window, so a large template on a large picture is slow.

## OpenCV to Rust

| OpenCV 5.1 | Rust |
|---|---|
| `cv::matchTemplate(img, templ, result, TM_SQDIFF)` | `imageproc::template_matching::match_template(&img, &templ, MatchTemplateMethod::SumOfSquaredErrors)` |
| `TM_SQDIFF_NORMED` | `SumOfSquaredErrorsNormalized` |
| `TM_CCORR` / `TM_CCORR_NORMED` | `CrossCorrelation` / `CrossCorrelationNormalized` |
| `cv::matchTemplate(img, templ, result, method, mask)` | `imageproc::template_matching::match_template_with_mask(&img, &templ, method, &mask)` |
| `cv::minMaxLoc(result, &min, &max, &minLoc, &maxLoc)` | `imageproc::template_matching::find_extremes(&scores)` |

## Performance comparison

| Operation | Input | OpenCV | Pure Rust | oximedia / oxipix | oxi / Rust |
|---|---|---|---|---|---|
| Template match (TM_SQDIFF) | 451x300 vs 40x40 grey | 1.609 ms | 121.900 ms | — (OXI-92) | — |

:::warning Performance difference

- **Template match (TM_SQDIFF):** imageproc template matching is 74.4x slower than OpenCV because it evaluates naive spatial O(W*H*w*h) sliding sums instead of FFT cross-correlation (oxipix support tracked in OXI-92).

:::
