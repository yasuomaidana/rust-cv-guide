## Goal

Turn a grey-level photograph into a black-and-white one (and a "keep the bright part" one) by thresholding, the way
`cv::threshold` does, and let Otsu's method choose the level. Both `imageproc` and `oxipix` (`otsu_threshold`) are shown side by side.

## Theory

Thresholding compares every pixel with a level `T`. `Binary` writes 255 where `src > T` and 0 elsewhere; `ToZero` keeps
`src` where it exceeds `T` and writes 0 elsewhere. Picking `T` by hand works when lighting is even. Otsu's method picks the
level that best separates the histogram into two classes (it minimises the variance inside the classes), which suits an
image whose histogram has two humps, such as bright coins on a darker background.

## Code

`imageproc::contrast` ships both `otsu_level` and all five `ThresholdType` modes. `oxipix::vectorize` provides
`otsu_threshold`; unified 5-mode `threshold(...)` helpers in **oxipix** are tracked in `OXI-89` (so the `oxipix` tab pairs
`oxipix::vectorize::otsu_threshold` with the five pixel comparisons).

//! OpenCV tutorial `tutorial_threshold` in pure Rust.
//! Run with `cargo run -p cvg-snippets --example threshold`.

use cvg_snippets::common::{Figure, describe, threshold_figures};
use image::GrayImage;
use imageproc::contrast::{ThresholdType, otsu_level, threshold};

/// `cv::threshold`: split at `level`, or at the level Otsu's method picks when `level` is `None`.
pub fn binarize(input: &GrayImage, level: Option<u8>, kind: ThresholdType) -> GrayImage {
    threshold(input, level.unwrap_or_else(|| otsu_level(input)), kind)
}

/// The coins, split at a fixed level and at the level Otsu's method picks, plus the `ToZero` variant.
pub fn figures() -> Vec<Figure> {
    threshold_figures(
        binarize,
        ThresholdType::Binary,
        ThresholdType::Binary,
        ThresholdType::ToZero,
    )
}

/// Describes one pixel of each figure.
pub fn report() -> String {
    describe(&figures(), 190, 150)
}

pub fn main() {
    println!("{}", report());
}

```rust
//! OpenCV tutorial `tutorial_threshold` using `oxipix::vectorize::otsu_threshold`.
//! Run with `cargo run -p cvg-snippets --example oxipix_threshold`.

use cvg_snippets::common::{Figure, describe, threshold_figures};
use image::{GrayImage, Luma};
use oxipix::vectorize::otsu_threshold;

/// Threshold mode matching OpenCV's five basic types (`0..=4`).
/// Unified modes in `oxipix` are tracked in `OXI-89`.
#[derive(Clone, Copy, Debug)]
pub enum Mode {
    Binary,
    BinaryInverted,
    Truncate,
    ToZero,
    ToZeroInverted,
}

impl Mode {
    /// Converts a dropdown index (`0..=4`) to `Mode`.
    pub fn from_index(kind: u32) -> Self {
        match kind {
            0 => Self::Binary,
            1 => Self::BinaryInverted,
            2 => Self::Truncate,
            3 => Self::ToZero,
            _ => Self::ToZeroInverted,
        }
    }
}

fn apply_mode(p: u8, t: u8, mode: Mode) -> u8 {
    match mode {
        Mode::Binary => {
            if p > t {
                255
            } else {
                0
            }
        }
        Mode::BinaryInverted => {
            if p > t {
                0
            } else {
                255
            }
        }
        Mode::Truncate => p.min(t),
        Mode::ToZero => {
            if p > t {
                0
            } else {
                p
            }
        }
        Mode::ToZeroInverted => {
            if p > t {
                p
            } else {
                0
            }
        }
    }
}

/// Applies `mode` at `level`, or computes `oxipix::vectorize::otsu_threshold` when `level` is `None`.
pub fn binarize(input: &GrayImage, level: Option<u8>, mode: Mode) -> GrayImage {
    let t = level.unwrap_or_else(|| otsu_threshold(input.as_raw()));
    GrayImage::from_fn(input.width(), input.height(), |x, y| {
        Luma([apply_mode(input.get_pixel(x, y).0[0], t, mode)])
    })
}

/// The coins, split at a fixed level and at `oxipix`'s Otsu level, plus `ToZero`.
pub fn figures() -> Vec<Figure> {
    threshold_figures(binarize, Mode::Binary, Mode::Binary, Mode::ToZero)
}

/// Describes one pixel of each figure.
pub fn report() -> String {
    describe(&figures(), 190, 150)
}

pub fn main() {
    println!("{}", report());
}
```

```rust
//! OpenCV tutorial `tutorial_threshold` with the `opencv` crate (calls native OpenCV).
//! Run with `cargo run --example threshold` inside `snippets-opencv`.

use cvg_opencv::{gray_mat, mat_gray};
use image::GrayImage;
use opencv::core::Mat;
use opencv::imgproc;

/// Binary threshold at `level`, or at Otsu's level when `level` is `None` (`cv::threshold`).
pub fn binarize(input: &GrayImage, level: Option<u8>) -> GrayImage {
    let (src, mut dst) = (gray_mat(input).expect("mat"), Mat::default());
    let kind = imgproc::THRESH_BINARY
        | if level.is_none() {
            imgproc::THRESH_OTSU
        } else {
            0
        };
    imgproc::threshold(&src, &mut dst, f64::from(level.unwrap_or(0)), 255.0, kind)
        .expect("threshold");
    mat_gray(&dst).expect("image")
}

pub fn main() {
    let coins = cvg_snippets::common::gray_sample("coins.png");
    println!(
        "foreground pixels: {}",
        binarize(&coins, None).iter().filter(|v| **v > 0).count()
    );
}
```

## Explanation

1. `sample("coins.png")` loads a photograph of coins. `to_luma8` makes it a grey image, as `cv::imread(..., IMREAD_GRAYSCALE)` would.
2. `otsu_level` (`imageproc`) and `otsu_threshold` (`oxipix`) compute the threshold from the histogram (`THRESH_OTSU` in OpenCV).
3. `threshold(&input, level, ThresholdType::Binary)` is `cv::threshold(..., THRESH_BINARY)`. Note the comparison is strictly greater than the level.
4. `ThresholdType::ToZero` keeps the original values above the level. Tests verify exact pixel parity across all five modes.

## OpenCV to Rust

| OpenCV 5.1 | Rust |
|---|---|
| `cv::threshold(src, dst, T, 255, THRESH_BINARY)` | `imageproc::contrast::threshold(&img, T, ThresholdType::Binary)` (`oxipix` unified modes tracked in `OXI-89`) |
| `THRESH_BINARY_INV`, `THRESH_TRUNC`, `THRESH_TOZERO`, `THRESH_TOZERO_INV` | `ThresholdType::{BinaryInverted, Truncate, ToZero, ToZeroInverted}` |
| `THRESH_OTSU` | `imageproc::contrast::otsu_level` or `oxipix::vectorize::otsu_threshold` |

## Performance comparison

| Operation | Input | OpenCV | Pure Rust | oximedia / oxipix | oxi / Rust |
|---|---|---|---|---|---|
| Otsu binary threshold | 384x303 grey | 0.030 ms | 0.045 ms | 0.159 ms | 3.53x |

:::warning Performance difference

- **Otsu binary threshold:** The oxipix threshold helper runs a per-pixel GrayImage::from_fn wrapper over otsu_threshold (~3.6x slower than imageproc's tight slice loop; native slice thresholding tracked in OXI-89).

:::
